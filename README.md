# CAN Monitor Desktop

Новый основной запуск проекта — desktop-приложение на Python без Flask, браузера и отдельного веб-сервера. CAN читается в фоне, GUI забирает сообщения из очереди, графики обновляются прямо в приложении, а сообщения пишутся только в CSV.

## Запуск

```powershell
py can_monitor_desktop.py
```

Если команда `py` недоступна:

```powershell
python can_monitor_desktop.py
```

При запуске приложение попросит выбрать папку, где будут храниться папки сессий. Внутри выбранной папки автоматически создается новая сессия:

```text
20260721_153012/
  can_messages.csv
```

Если закрыть диалог выбора папки, будет использована папка `sessions` в каталоге проекта.

## Рабочий процесс

1. Выберите папку для сессий при старте.
2. При необходимости откройте шаблон проекта через кнопку `Открыть шаблон`.
3. Можно выбрать JSON-файл или встроенный шаблон. Во встроенных есть `МИД`.
4. Выберите CAN-канал и скорость.
5. Нажмите `Подключить`.
6. Добавьте сигналы вручную или выберите найденный CAN ID в списке `Найденные ID` и нажмите `Из ID`.
7. Для завершения текущей записи нажмите `Новая сессия`. Подключение к CAN не перезапускается, но дальнейшие сообщения начнут писаться в новую папку с новым `can_messages.csv`.

## CSV

CSV пишется постоянно во время приема сообщений. JSON-файлы больше не создаются новым desktop-приложением.

Основные поля CSV:

- `Record_Number`
- `Session_Elapsed_s`
- `Wall_Time`
- `Channel`
- `CAN_ID_Dec`
- `CAN_ID_Hex`
- `Frame_Type`
- `RTR_Status`
- `Length`
- `Data_Hex`
- `Byte_0` ... `Byte_7`
- `Timestamp_Raw`
- `Parsed_Signals`

## Шаблоны проекта

Рекомендуемый формат шаблона — JSON. Пример лежит в `project_template.example.json`.

```json
{
  "version": 1,
  "name": "Example CAN project",
  "channel": 1,
  "baud_rate": 500000,
  "history_seconds": 600,
  "signals": [
    {
      "message_id": "0x181",
      "name": "Value",
      "channel": 1,
      "type": "float32",
      "byte_order": "little_endian",
      "start_byte": 0,
      "length": 4,
      "scale": 1.0,
      "offset": 0.0,
      "first_bytes": "",
      "match_offset": 0,
      "match_bytes": ""
    }
  ]
}
```

Также поддерживается старый формат `can_signals_config.json` из веб-версии, где верхний уровень был словарем `{signal_key: parser_config}`.

Для сообщений, где один CAN ID несет несколько типов данных, можно использовать `match_offset` и `match_bytes`. Например, для МИД код сообщения находится в байтах 2-3, а значение в байтах 4-7.

## Встроенный шаблон МИД

Шаблон `МИД` строит сигналы для цилиндров `A1` ... `A12` и `B1` ... `B12`.

CAN ID берутся из кода модуля измерения детонации:

- `A1` начинается с `0x10F`, далее до `A12 = 0x11A`.
- `B1` начинается с `0x11B`, далее до `B12 = 0x126`.

Для каждого цилиндра можно галочками выбрать:

- `Детонация`: код `3`, `float32`, байты 4-7.
- `Смещение`: код `2`, `float32`, байты 4-7.
- `Счетчик ошибок`: код `1`, `uint32`, байты 4-7.

## Зависимости

Новый desktop-запуск использует стандартную библиотеку Python: `tkinter`, `ctypes`, `csv`, `threading`.

Для работы с реальным CAN-оборудованием рядом должен быть доступен `chai.dll`, как и раньше. Если DLL не загружается, существующий `can_receiver.py` автоматически включает demo-режим.

## Старый веб-интерфейс

Файлы `server_save.py`, `templates/` и `static/` оставлены в проекте как наследие. Старый запуск все еще возможен:

```powershell
py server_save.py
```

Для нового сценария он не нужен.
